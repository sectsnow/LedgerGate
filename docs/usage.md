## 首次配置

1. 在“上游账户”添加 NewAPI 或 Sub2API 的站点根地址。账户访问令牌用于后台采集，NewAPI 按站点要求填写用户 ID。需要验证码或二步验证的站点使用账户令牌。
   Sub2API 可同时填写配套的 Access Token 和 Refresh Token。编辑时两个字段均留空会保留已保存的值，单独更换 Access Token 会清除旧 Refresh Token。输入框的“显示／隐藏”可切换明文，已保存的令牌由管理员点击显示或复制时按需读取；仅查看、复制不会把令牌作为新值提交。新填 Refresh Token 未配套填写 Access Token 时，会就地提示并阻止保存。两个令牌均加密保存，账户列表仅返回是否已保存。
2. 在下拉框中选择上游实际使用的余额单位，其他单位选择“自定义”。NewAPI 默认每单位为 500000 原始配额，需以实际站点配置为准。余额阈值默认 0，如需余额告警再设置正数。点击“采集”检查状态。
3. 在账户卡片点击渠道数量，进入该账户的渠道管理。新增时自动填写账户和站点地址，选择上游分组后可在上游生成密钥并自动保存为本地渠道，也可切换为手动填写已有 Key。“转发渠道”提供按账户分组的总览，支持搜索账户、渠道、模型和协议；未关联账户的渠道归入“直连供应商”。
4. 在“模型路由”设置客户端模型名与上游模型。渠道选项显示“账户 / 渠道”，可组合不同账户的渠道。加权轮询将请求按权重分摊，优先级模式按数字从小到大选择。
5. 在“网关密钥”创建以 `sk-` 开头的客户端密钥。创建弹窗和列表均可复制完整密钥，支持局域网 HTTP 访问。旧版仅保存摘要的密钥无法恢复完整内容，需要时创建新密钥。
6. 如需推送告警，在“系统设置 → 通知推送 → 通知渠道”新增接收方式，保存后点击该渠道的“测试”。

例如创建名为 `personal-assistant` 的模型路由后，本机源码部署的 API Base URL 为 `http://127.0.0.1:8080/v1`，模型名设置为 `personal-assistant`。Docker 默认使用宿主机 8081 端口，局域网客户端需将地址替换为服务器 IP。将网关 Key 设置为客户端密钥；下例从环境变量 `LEDGERGATE_API_KEY` 读取。

```bash
curl http://127.0.0.1:8080/v1/chat/completions \
  -H "Authorization: Bearer $LEDGERGATE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"personal-assistant","stream":true,"messages":[{"role":"user","content":"你好"}]}'
```

网关提供 `GET /v1/models`、`POST /v1/chat/completions`、`POST /v1/responses` 和 `POST /v1/messages`。推理入口接受 `Authorization: Bearer ...` 或 `x-api-key`。

## 余额单位与余额告警

“余额单位”提供美元、人民币、欧元、港币、日元、英镑、USDT、积分和自定义选项。该单位用于标记和按币种汇总上游余额、消费，不做汇率换算；网关请求费用仍以美元估算。已有自定义单位在编辑时保留。

“余额阈值（低于此值发告警，0 = 不告警）”的规则如下：

| 设置 | 行为 |
| --- | --- |
| `0`，新建账户默认值 | 关闭余额告警，包括余额为负数的情况。 |
| 大于 `0` | 成功采集的余额低于此值时告警，等于阈值时不告警；可填写小数。 |
| 编辑已有账户 | 保留原阈值，需要关闭时手动改为 `0`。 |

“最新余额确认耗尽时暂停关联渠道转发”是独立开关。关闭余额告警后，它仍可在最新成功采集确认余额小于或等于 0 时暂停转发。

## 功能详解

### 页面导航

- **总览**：运行概览，快速查看今日情况和当前问题。
- **分析与排障**：统计分析、请求记录，分别用于汇总对比与逐条排障。
- **接入与调度**：上游账户、转发渠道、模型路由、模型测试、网关密钥。
- **监控与系统**：监控中心、系统设置。原告警、倍率变动和公告链接仍可访问，会转入监控中心对应标签。

运行概览、账户、渠道、模型、密钥和监控中心每 15 秒刷新当前页所需数据；请求记录保持自身每 2 秒刷新。统计分析和系统设置按需加载，可手动刷新；离开页面会取消旧页面的数据读取。

### 运行概览

- 六张关键卡片显示上游账户余额、今日上游实际消费、今日请求、今日 Token、今日网关费用估算和可用渠道。余额与实际消费按币种单独查看，列出采集覆盖及时间；网关估算固定为美元，与上游账单分开核对。
- 今日趋势按北京时间零点至当前展示请求量、Token 和费用估算。当前问题最多预览 5 项，包括采集异常、低余额、渠道冷却或自动停用、通知投递失败；暂停监控与手动停用不计异常，完整记录在对应管理页查看。
- 最近请求最多显示 5 条，进行中优先，可打开完整详情；未获得用量或尚未核算费用时显示等待或未知。所有请求、筛选和排障功能在“请求记录”查看。

### 统计分析

- 分为“综合、用量趋势、缓存分析、稳定性、费用与资产”五个标签。综合保留完整渠道与模型表现表；其他标签集中展示对应指标，避免首页与表格横向堆积。
- 网关统计支持今天、近 24 小时、7 天、14 天、30 天及保留范围内自选日期；卡片、趋势和表现表使用同一时段。支持按统一模型筛选，按请求量、缓存命中率或首次成功率等排序；选择会在本机保存。点击“详细分析”进入独立页面，返回时保留筛选和列表位置。
- 请求趋势提供请求量（总请求、失败／取消）、Token 用量（输入、输出）、费用估算（美元）三个指标视图，曲线不叠加，保留实际零值及峰谷。失败／取消已计入总请求；费用未知的请求不计入估算，全部费用未知的时段留空，部分未知时显示已估算小计及未知数量，以上游实际结算为准。悬停、点击或聚焦后用左右方向键查看每个时间点，Home／End 跳转首尾。今天按北京时间零点至当前统计，近 24 小时包含当前及之前 23 个小时，多日范围按北京时间自然日计算；自选范围包含首尾日期，长范围图表可左右滚动，超出保留周期时显示提示。
- “用量趋势”保留近一年网关请求活跃度热力图，按北京时间汇总每天已结束请求的数量、Token 和费用，支持悬停、点击和键盘查看。内存详情淘汰或服务重启后仍可查看每日汇总，图中显示汇总保留周期。
- 渠道与模型表现包括请求量、成功率、平均总耗时、平均首字、平均 TPS、Token 和费用。平均 TPS 按输出总 Token 除以请求完整耗时之和计算，包含思考与等待；平均首字只使用新语义口径记录，旧口径及缺失时间不补造。缓存、稳定性及费用详细口径见下文对应说明。
- “费用与资产”按币种汇总账户总余额、今日实际消费和累计实际消费，保留最低余额账户与余额／消费历史。上游资产时段独立于网关统计，支持最近 7 天、14 天和 30 天，默认 7 天，使用每天各账户最后一次有效采集快照。暂停监控不影响已有历史数据的展示；当日仅采集到部分账户时显示已采集部分的合计，通过文字及覆盖数量说明。相邻日期有数据时以实线连接，参与账户或覆盖数量变化不打断连线；余额与消费分别判断，无记录的日期留空。左轴为余额、右轴为消费，单位跟随当前币种。不把暂停账户的旧余额或昨日消费冒充为当日数据；账户列表可查看各自最后余额与今日消费。

### 系统设置分区

系统设置分为“基础设置、运行参数、通知推送、桌面小组件、数据与备份、关于”。主题与密码在基础设置，网络代理、超时、采集并发及同步周期在运行参数，通知渠道和告警门槛在通知推送，历史保留、配置导入导出及完整备份在数据与备份，版本信息在关于。运行、通知及保留参数保存前会重新读取设置，只覆盖当前分区字段，保留其他分区的最新值。

### 上游账户与监控

- NewAPI / Sub2API 账户管理，支持账户令牌和基础账号密码登录。编辑弹窗默认收起 Logo 设置，点击“修改图标”展开；取消与保存按钮固定在弹窗底部，滚动时仍可操作。
- 账户列表自动显示上游网站图标，优先读取同源站点声明的图标或明确标为 Logo 的主页图片，再尝试 `/favicon.ico`；获取不携带账户凭据。成功后将小图保存在本地数据库，重启后直接读取，离线也能显示；失败结果仅在内存缓存 1 小时，N／S 占位图标可点击重试。最大下载 4 MiB，超过 512 KiB 的 PNG、JPEG、GIF 位图缩为最长边 128 像素的 PNG，保存的图片不超过 512 KiB。编辑已有账号时可选择或拖入图片并“上传 Logo”，手动图标优先使用；“恢复自动获取”会移除已保存图标并重新抓取。Logo 随账号配置导入导出，也包含在完整备份中；已有账号只补齐缺失图标，保留本地已保存图标。旧配置包没有 Logo 时继续自动获取。
- 包含 Logo 的 `.lgd` 配置包使用 v2 格式，导入端需要支持该格式；不含 Logo 时继续导出 v1，旧版 v1 配置包仍可导入。图标随完整数据库备份保存，无需另备份图片目录。
- 编辑账号时点击“获取网站图标”，可预览站点声明的 favicon、触屏图标和明确标为 Logo 的主页图片，也支持站点声明的公网 CDN 图标。相同图片去重，校验失败的候选不展示；选择后点击“使用该图标”才替换当前 Logo，获取失败或尚未确认时保留原图标。获取过程不携带账户凭据，并沿用该账号的全局代理设置；页面通过后端返回的图片预览，不直接请求外站。站点未公开图标或需要执行脚本、通过访问验证时，仍可手动上传。
- 已知图片直链时，也可在“图片地址”中填写公网 HTTP(S) 地址，点击“下载并保存”。后端沿用账号的代理设置下载并校验图片，成功后作为手动 Logo 保存，重启和导入导出后保留；下载或校验失败不修改当前 Logo。不支持内网、带账号密码或需要登录的地址，大小限制与文件上传一致。
- NewAPI 密码登录兼容旧版会话和新版 Access Token + `new_api_refresh` Cookie，自动轮换刷新令牌。只有明确的 401 才尝试重新认证，403 不反复登录；登录附加 JSON 参数加密保存。
- 账户卡片按“正在监控”和“已停止监控”分栏，以绿色和橙色标识；展示上游返回的全部可用分组和倍率，默认预览 4 个，支持展开、收起。账户页可一键暂停或恢复监控：暂停同时阻断关联渠道和模型路由的新请求，没有可用路由的模型从客户端模型列表隐藏；恢复后按原配置重新可用，并立即安排采集。共享模型的其他可用渠道继续转发，手动停用或因上游异常自动停用的渠道保持停用。历史数据、手动采集和路由配置保留，已经发出的请求及采集可完成。
- Sub2API 支持 Access Token 和可选的 Refresh Token，访问令牌失效时自动续期并重试采集。账号密码登录会保存上游返回的两个令牌，续期失败且需要重新认证时尝试重新登录。
- 定时或手动采集余额、累计消费、倍率、公告和 Sub2API 订阅快照。部分扩展接口不可用时会显示采集警告。
- 账户卡片显示今日消费，历史快照记录采集当日消费。NewAPI 按北京时间自然日查询，Sub2API 使用上游统计的今日实际消费，跨日后过期的今日金额不再显示。
- 概览“今日上游实际消费”及统计分析“今日总消费”同时显示参与合计账户中最早的成功采集时间，属于定期采集结果而非实时账单；采集失败不会更新该时间，历史记录没有时间时不补造。请求费用估算则随已结束请求累计，按请求完成时的价格核算，以上游实际扣费为准。
- Sub2API 累计消费读取站点用量统计中的累计实际消费，覆盖接入 LedgerGate 之前的消费。采集失败时保留上次可用数据并显示警告。
- 低余额、监控失败、监控恢复、倍率变化、公告更新，以及订阅到期和低余量告警。新账户的余额阈值默认为 0（关闭余额告警），设置为正数后仅在余额低于阈值时告警。
- 监控中心分为告警、倍率变动和上游公告三个标签，支持按账户筛选、搜索和分页。倍率变动保存具体分组、前后倍率与涨跌幅，记录分组新增和移除；首次采集建立基线，旧告警不补造缺失的数值。告警及倍率记录沿用监控历史保留设置，默认 30 天。
- 上游公告汇总各账户最近一次完整采集返回的列表，支持查看标题、来源、发布时间和全文，兼容 NewAPI 单条站点公告与 Sub2API 公告列表及分页。采集失败保留上次公告并标注，已读状态和列表顺序变化不会误报更新；上游未提供的历史公告或发布时间不补造。
- 消费、倍率、公告和订阅等部分采集失败及恢复也会记入告警。倍率和公告每次真实变化均保存本地记录，Webhook 仍遵循通知冷却时间，冷却期间标注为仅记录。

### 网络代理

- 系统设置可配置一个 HTTP、HTTPS 或 SOCKS5 出站代理，支持加密保存用户名密码及草稿连通性测试。账户与渠道各自勾选“使用全局代理”：账户用于登录、令牌续期与采集，渠道用于转发、模型同步与模型测试；新建和导入渠道默认继承账户选项。全局关闭时直连，代理连接失败不会自动降级直连。代理地址须从服务器或容器可达，`127.0.0.1` 指服务器或容器自身；对象的直连设置不受 `HTTP_PROXY` 等环境变量覆盖。公共价格目录仍直连。

在“系统设置 → 运行参数 → 网络代理”填写协议、主机、端口及可选认证信息，点击“测试代理连接”验证当前草稿，再保存并启用。测试不保存配置，也不调用账户接口；显示目标 HTTP 状态和耗时。已保存的密码留空保留，勾选“清除已保存的代理密码”才会清除。全局开关和账户、渠道各自的开关需同时开启才走代理。

### 告警与通知

- 本地告警记录、持久化告警冷却、JSON Webhook、可选 HMAC-SHA256 签名、失败重试。
- 通知支持 Telegram、通用 Webhook、Email、企业微信、钉钉、飞书和 Server酱，可添加多条独立渠道，按账户与事件订阅，分别启停、测试、查看投递记录并设置尝试次数。倍率变化幅度、订阅余量和临近到期阈值在系统设置调整，真实变化仍保留本地记录。

### 渠道与模型

- 一个账户关联多条渠道，每条渠道分别保存转发 API Key，也支持直连供应商。
- 账户卡片和账户渠道页支持导入已有 API 密钥。点击“导入渠道”或“导入已有密钥”，可分页勾选 NewAPI / Sub2API 的密钥并选择协议，保存后创建关联渠道。已有或重复密钥会识别为现有渠道，停用、过期和额度耗尽的密钥会拦截。完整上游密钥由服务端读取并加密保存。
- 新增关联账户的渠道时，可选择“在上游生成新密钥”，实时读取可用分组及倍率，按所选分组在 NewAPI / Sub2API 创建密钥，并将完整密钥加密保存在本地渠道，立即显示分组倍率。新密钥默认不限额度、不过期，上游名称附带用于重试识别的短标记。创建进度持久化保存，原窗口保持相同参数重试会继续保存同一把密钥；创建结果不明确时先查询，避免重复生成。也可继续手动填写已有密钥。
- 一条渠道可勾选多个上游协议。转发时优先使用与客户端相同的协议，需要转换时选择已勾选且能够表达该请求的协议；既有单协议渠道可继续使用。
- 渠道总览按账户折叠展示，搜索会展开匹配分组，长列表可在分组内滚动。删除时在页面内确认，并列出受影响的模型及剩余路由数；确认后原子删除本地渠道和对应路由引用，空模型可重新编辑添加上游。
- 渠道列表支持直接切换启用状态。停用后保留路由配置，模型路由中的对应渠道标灰且不可选，网关跳过停用渠道，包括故障切换期间刚被停用的备用渠道；重新启用后恢复参与转发。
- 账户连续两次完整采集都确认同一密钥的具体分组不在可用列表中、且没有倍率时，自动停用关联渠道，显示原因并记录告警。接口失败、列表不完整、未匹配密钥、仅缺少倍率、0 倍率及 NewAPI 自动分组不会据此停用。自动停用保留路由，恢复后需手动启用。
- 渠道勾选后显示批量操作栏，清空选择后自动收起。支持逐条勾选、按账户分组全选或全选当前筛选结果，批量启用、停用、修改协议、同步模型和删除。单次最多 100 条，逐条返回结果，失败项继续保持选中以便重试。批量删除需确认路由影响，同步模型同时最多请求 4 条渠道，失败时保留原模型列表。
- 渠道列表显示密钥所属分组及实际倍率，账户详情提供基础倍率与实际倍率表。Sub2API 合并分组基础倍率和用户自定义倍率；NewAPI 使用用户分组倍率。按上游密钥 ID 或完整密钥匹配，不按渠道名称推测，缺失倍率明确标出；采集失败时标注上次可用数据。
- 点击渠道的模型数量或展开渠道编辑中的“模型列表”，可搜索、逐条改名和删除、勾选批量删除、批量添加或整体编辑模型 ID。修改在保存渠道后生效，自动去重，并检测并发同步或编辑；已有模型路由另行管理。
- 单条或批量同步渠道模型时先弹窗预览上游返回的模型，支持搜索、全选筛选结果和逐项勾选。已有模型默认选中，新增模型默认不选；上游未返回的已有模型仍保留，可取消勾选后移除。确认后保存勾选项和本次检查结果，取消、获取失败或未选择模型的渠道保留原列表。保存前校验预览版本，已有模型路由保留。
- 模型别名、上游模型映射、模型列表同步、手动选择、加权轮询、优先级故障转移、失败冷却和单请求恢复探测。新增模型默认手动选择，并使用第一条路由，可在模型列表中切换当前路由。
- 模型路由页可切换“最近使用”，只展示当前已配置且有已结束请求的模型，统计当前小时及前 23 个小时，按请求数、最后请求时间、模型 ID 排序，最多显示 5 个。失败请求和同名模型测试也计入；搜索仅筛选这 5 个模型，统计读取失败时保留上次结果并提示。
- 模型路由页勾选模型后显示批量操作栏，取消全部勾选后自动收起。支持删除所选、全选当前筛选结果后删除，也可清空全部模型。确认框列出模型名称；删除模型及其路由配置，保留渠道、渠道保存的模型列表、内存中的近期请求和持久化用量统计。部分失败时保留失败项的勾选，可查看原因后重试。
- 模型路由支持拖动左侧手柄或用上下方向键排序。拖动时整行跟随并带阴影，相邻行平滑让位，松开后落位并自动保存，保存失败恢复原顺序。优先级从上到下设为 0、1、2…；加权轮询按 N、N−1…1 设置权重，越靠上分配越多；手动模式只调整显示顺序。排序保留模型价格、路由 ID 和手动选择，检测到并发修改时拒绝覆盖。
- 模型路由页支持“从渠道生成”，默认使用已保存的渠道模型列表，尚未获取过列表时自动同步，同名模型合并渠道。可勾选重新同步上游，明确替换手工编辑的列表。新模型默认手动选择；再次生成会补充缺少的路由，并保留已有模型的调度、单价与路由配置。同步失败和空模型列表会逐渠道提示，可检查后重试。

### 模型测试

- “模型测试”可指定渠道、已保存或临时输入的 Key、OpenAI Chat / Responses / Anthropic 协议，单个或批量测试文本模型。支持流式、1–10 并发、输出上限、取消，展示首字、总耗时、Token、缓存用量、费用估算和响应或错误原因。
- 请求协议保存在当前浏览器，切换 Key、渠道或重新打开页面会继续使用上次选择；浏览器禁用存储时仅保留当前页面的选择。

### Windows 桌面小部件

- 面板使用随主题变化的阴影与透明留白，关闭透明窗口的系统阴影，减少浅色外沿；自动调整高度时计入留白，浮标尺寸保持原有设置。
- “总览”按账户资产、用量、告警、排行、分析趋势排列，默认全部展开；可点击分区标题折叠并记忆，其他标签可单独查看对应内容。分析内部的缓存效率、请求质量、延迟与重试、缓存成本、错误分类、延迟对照和缓存趋势也可分别折叠；默认全部展开，跨视图与重启保留选择，“展开总览全部分区”同时恢复内部小节。有异常时在“告警”标签显示提醒计数，一般统计说明不计入该计数。切换视图、折叠分区或调整字号时自动按内容调整窗口高度，保留当前宽度；达到屏幕工作区或窗口高度上限后滚动查看，仍支持手动调整窗口大小与位置记忆。
- 账户资产可展开采集详情，按账户列出低余额、未采集、暂停、失败、跨日、缺失项目及超过两个采集周期未更新的情况。低余额沿用服务端设置的告警阈值，不自行把零余额判为告警。分别显示上游检查时间和今日消费成功采集时间；底部“获取于”仅代表小部件读取 LedgerGate 快照的时间。缺失时间保持未知，不拿检查时间替代消费时间。小部件只读接口增加账户 ID、名称、采集周期、消费采集时间及固定分类提醒，不返回账户凭据、站点地址或原始上游错误。
- 标题栏齿轮进入“小部件设置”，统一管理连接、阅读方式、浮标和启动版本选项。支持舒适/紧凑两种密度与标准/大字两档字号，选择保存在本机；金额默认显示两位小数，悬停可查看完整精度。阅读设置仅影响面板，浮标保持原有尺寸。
- 设置中可主动开启当前 Windows 用户的登录自启动；默认不写入启动项，不需管理员权限。便携版需保留 EXE 的路径，移动后重新开启；安装版升级保留启动项，正常卸载时仅清理指向本安装路径的启动项。版本区展示当前小部件版本，点击“检查更新”才访问固定的 GitHub 正式 Release 接口，不发送 LedgerGate 地址或只读凭证；发现更新后可查看说明、下载安装包或便携 EXE，不自动替换程序。
- 标题栏的“收起为数据浮标”把面板收成 72×56 逻辑像素的数据胶囊；单击浮标展开，保留原视图、周期、主题和面板宽度，再按内容适配高度。浮标可拖动，位置与完整面板分开保存；关闭按钮仍是隐藏到托盘。托盘可显示完整面板或重置窗口位置。
- 在“小部件设置 → 浮标与贴边”中管理自动收起、保持展开、全屏避让及指标轮播。拖到显示器左、右外边缘约 16 逻辑像素内会吸附，拖离约 32 像素脱离；相邻显示器接缝不吸附。贴边面板在鼠标离开且失焦 800ms 后自动收起；打开设置、颜色菜单或选择保持展开时暂停。浮标默认避让所在显示器的前台全屏应用，退出后恢复，不主动取得焦点。
- 浮标可显示今日 Token、今日请求、所选币种余额或今日实际消费，独立于面板的近 7/30 天选择；多币种不合计。默认不轮播，可选每 8 秒切换，悬停、拖动和右键菜单打开时暂停。悬停使用系统提示显示精确值、获取时间及采集覆盖；右键切换指标、打开设置或隐藏到托盘。断线、超过 90 秒未刷新或跨北京时间日期会标记旧数据，缺失值显示“—”。指标轮播不发请求，托盘隐藏时停止数据轮询，恢复后重新读取。
- 在 LedgerGate“系统设置 → 桌面小部件”可下载与当前版本对应的 Windows 安装包或便携版 EXE，下载地址指向该版本的 GitHub Release。
- GitHub Actions 的“构建 Windows 桌面小部件”工作流支持手动运行，也会在相关源码或正式版本标签推送时构建；工作流产物 `LedgerGate-Widget-Windows-x64` 包含独立 EXE 和安装包，保留 14 天。发布时需将 `LedgerGateWidget-Setup-x64.exe` 和 `LedgerGateWidget.exe` 附到同版本 Release，供设置页下载。
- 在 LedgerGate“系统设置 → 桌面小部件”生成只读凭证，复制仅显示一次的凭证；启动小部件，填写 LedgerGate 的服务器地址和凭证。该凭证只允许读取小部件概览及模型、渠道汇总，不能登录管理页面或调用网关；重新生成或撤销会使所有使用旧凭证的小部件失效。小部件将凭证使用 Windows 当前用户的 DPAPI 加密保存在用户目录，不保存管理员密码。
- 悬浮卡片每 30 秒读取 LedgerGate 已采集的数据，支持拖动、置顶、隐藏到托盘和打开控制台；不会因刷新卡片而触发上游采集。内容可在“总览、账户、分析、告警、排行”五种视图间切换，选择会保存在本机。分析视图会拆分输入／输出 Token、缓存读写、平均 Token／请求、错误率和费用估算，并显示请求与 Token 的按日走势图；无汇总的日期会保留为空档。告警视图区分当前异常和周期统计：连接或操作失败、账户异常、旧快照计入关注数量；周期请求错误、费用未知、保留周期不足和旧服务说明保留展示，不增加关注数量。主动暂停的账户不计异常。页面通过标签手动切换，不再自动轮播。可从标题栏的颜色风格按钮选择跟随系统、云白、深海蓝、翡翠绿或暮光紫。余额和今日实际消费按币种分开展示；请求、Token、缓存、费用估算及模型与渠道排行可切换今日、近 7 天和近 30 天，均按北京时间自然日和已保留记录统计。费用估算与上游实际消费分开展示，费用未知的请求不会计入估算；汇总保留天数不足时会提示。部分账户未采集或异常会提醒；暂停账户仅显示状态说明，连接失败时保留上次结果并标明时间。关闭窗口会隐藏到托盘，可从托盘重新显示或退出。
- Windows 程序需要 Microsoft Edge WebView2 Runtime；独立 EXE 使用系统已安装的运行时，安装包在缺失时尝试联网安装。远程连接建议使用 HTTPS。完整备份包含当时的小部件凭证摘要，恢复后以备份中的凭证状态为准；选择性配置数据包不包含该凭证。

浮标与贴边功能从 v0.1.14 起提供。自动测试及 Windows 目标编译通过不等于 Windows 实机验收；透明圆角点击、全屏避让、屏幕热插拔及休眠/远程桌面恢复仍待目标环境确认。

小部件的账户、排行、监控记录和缓存／稳定性／费用分析提供对应控制台入口，底部“打开控制台”也随当前视图进入相关页面。仅在已配置的服务地址下打开固定页面，不传递只读凭证；统计周期与筛选以控制台当前设置为准。新的分析与监控入口需要配套此次服务端导航布局，旧版服务端可能无法识别这些子页。

采集详情、总览折叠、阅读设置及启动/更新设置从 v0.1.15 起提供。配合旧服务端使用时，缺少的账户名称使用序号代称，消费采集时间显示未知；完整详情需要服务端同步升级。登录自启动的真实 Windows 登录效果仍待实机验证。

小部件的总览用量区补充缓存命中率、首次成功率与费用覆盖率；分析区展示缓存 Token 命中率、命中请求占比、读写用量（含 5 分钟／1 小时写入）、缓存字段覆盖率、重试后成功次数及已知费用样本的平均每请求费用。命中率使用同一批有效缓存样本的读取 Token 总量除以输入 Token 总量，不平均单次百分比；未提供字段不算零命中。主动暂停的账户以“已暂停”显示，不计入账户异常。

服务端启动时自动为每日汇总增加缓存样本计数，已有汇总不反推样本；后续请求结束时与原用量在同一事务中累计，重启和摘要清理不丢失这些计数。历史缓存用量合计仍保留，缓存命中率只代表有明确字段的有效样本，覆盖率用于说明完整程度。旧服务端未提供新增字段时显示“—／未记录”，完整指标需服务端与小部件同步升级。升级前备份完整数据目录；旧版降级后不会继续更新新增缓存计数，往返升级可能降低覆盖率，但不改变原有费用记账。

详细分析补充未缓存输入（有效缓存样本）、重试挽回率与额外等待、错误分类分布、首字／总耗时 P50/P95、同渠道同模型同流式模式下缓存命中与未命中的延迟对照、缓存净节省估算和命中率趋势。管理网页从统计分析对应行的“详细分析”进入独立页面；小部件在完整总览和分析区展示。

- P50/P95 来自小时汇总内的毫秒分布桶，采用最近秩的桶上界近似值，单桶相对误差小于 6.25%，不由平均值推算；语义首字与总耗时分别显示有效样本数，未记录历史不补造。
- 重试挽回率＝最终被重试救回的请求数 ÷ 首次失败且非取消的请求数；分母包含没有再次尝试的首次失败。额外等待平均以有尝试记录的请求为分母，未重试请求贡献零等待。
- 错误只保存固定分类计数，不落盘错误原文；分布覆盖率显示其样本范围。缓存与延迟对照只统计成功且明确返回缓存读取字段的请求，按渠道、模型、流式模式分组，首字另列样本数；仅供观察，不认定缓存造成了延迟差异，最多显示样本最多的前 20 组。
- 缓存净节省以请求当时的单价和倍率计算并冻结保存两种输入成本的合计：全部按普通输入计价，与实际普通输入＋缓存读取＋5 分钟／1 小时写入计价。负值表示净增费用；价格、倍率或缓存用量字段不完整时不纳入节省样本，并显示覆盖率。不用后来的报价重算历史，不代表上游实际扣费。
- 缓存趋势使用每时段同批有效样本的缓存读取量除以输入量；今日／近 24 小时按小时，多日按北京时间自然日展示。无样本、无有效输入量的时段留空并断线，明确的零命中仍保留；提供逐时段的数据列表。
- 分布、固定分类和估算合计随请求结束在同一记账事务中保存于小时汇总，随原汇总保留周期清理，并包含在完整备份中；不会额外持久化正文。升级只新增小时汇总字段，历史缺失分布、分类和价格样本保持未知。完整功能需服务端与小部件同步升级。

### 网关与调度

v0.1.15 新增周期预算与并发限制、跨重启请求摘要、同模型渠道比较和分项采集状态的配置与数据边界，见[网关预算、排障摘要与采集状态](gateway-controls.md)。

“渠道与模型表现”保留完整综合表，并提供缓存、稳定性、费用三种指标视图；支持按统一模型筛选、按缓存命中率或首次成功率排序。缓存命中率与小部件使用相同有效样本口径，展示读取／写入覆盖率；平均每请求费用仅以费用已知请求为分母，并标出费用核算覆盖率。渠道／模型缓存统计按小时在请求结束时持久化，旧小时汇总不反推缺失样本，已有明确用量标记的旧逐条记录在原迁移过程中可汇总；原有记账、备份和历史保留机制继续使用。

- OpenAI Chat、OpenAI Responses、Anthropic Messages 三种入口，同协议转发及双向转换。
- 非流式和 SSE 流式转换，支持文本、function 工具调用与工具结果，消息中的图片 URL / base64。
- 管理员会话、网关密钥创建与撤销、请求用量、费用估算和历史记录保留。
- 网关密钥可编辑启用状态、允许使用的模型、有效期和累计预算。费用累计独立于请求日志保留周期，升级时从尚保留的历史请求初始化；达到上限后阻止新请求，进行中的请求仍可能产生费用。
- 优先级故障转移可在“编辑模型路由”中设置单成员总尝试次数、同成员重试间隔、失败冷却和切换后亲和时间，默认分别为 2 次（含首次）、3 秒、60 秒、300 秒。临时连接失败、5xx 和输出前超时先重试当前成员，耗尽后再切换；恢复探测也遵守同成员尝试次数，重试等待期间保留单请求探测占用，其他请求继续使用备用成员。备用成功后在亲和期内继续使用，期满只允许单个请求探测恢复，亲和设为 0 可关闭。停用当前渠道、暂停账户或修改路由后重新选路。既有模型调度模式不自动改变，旧配置和旧配置包未包含这些字段时使用默认值，重启后运行中的亲和状态重新建立。
- 系统设置可调整首个有效输出、流空闲、整次请求超时、整次请求最多尝试次数与账户采集并发；同成员重试和等待共用整次请求预算。参数错误直接返回，鉴权错误跳过对应凭据，模型相关错误只冷却当前路由，明确连接或鉴权故障才影响整个渠道。429 不立即重试当前成员，并遵循 `Retry-After`（最长一小时）；客户端取消和网关本地错误不触发渠道冷却或后续重试。
- 自动选路时，所有可选成员都在临时故障冷却或恢复探测中，请求会在总时间预算内等待并重新检查可用性；等待不计入上游尝试次数，实际调用仍受最多尝试次数约束。客户端取消立即停止等待，停用、账户暂停及路由变更会在短间隔检查时生效；参数错误、鉴权错误、模型不存在以及没有启用成员时不进入这种恢复等待。手动选择模式保留原行为，选定成员不可用时直接报错，由用户切换。
- 模型路由页每 2 秒更新当前成员、恢复探测、冷却范围及截止时间、备用亲和截止时间。请求卡片显示等待重试和选路说明，详情逐次记录重试、切换及探测原因。尚未识别到实际内容的流标为“已接收响应”，不把初始化事件等同于首 Token；首响应、流无数据、完整响应及总预算超时分别说明原因，尝试次数耗尽时保留最后一次上游错误。
- 同协议保留客户端 User-Agent、相应协议的版本及扩展请求头；上游认证始终使用渠道密钥。返回限流头及 `X-Upstream-Request-ID` 供关联上游记录，网关自己的 `X-Request-ID` 保留，响应 Cookie 不转发。Chat 与 Responses 可互转 text、json_object、json_schema 输出格式；跨协议工具选择保留是否允许并行调用，无法表达的其他扩展继续明确报错。
- 选路前先筛选能表达本次请求的成员，再按原策略调度；跳过不兼容成员不计入上游尝试次数，也不触发冷却。手动选择仍固定使用所选成员，全部可选成员不兼容时返回明确错误。Chat 与 Responses 之间保留通用 metadata 和 user；跨 Anthropic 时 user 对应 metadata.user_id，无法表达的通用 metadata、其他流选项或多候选要求会明确拒绝。
- 请求及每次尝试分别显示上游结束原因，区分正常结束、Token 上限、内容过滤、工具调用和未知未完成原因；合法的未完成终态不作为渠道故障。每次收到上游 HTTP 响应都会保存其状态码及请求 ID，便于核对中转站记录；网关转发结果与上游 HTTP 状态分别展示，未收到响应时不补造上游状态。
- 系统设置“关于”中的“运行版本”展示前端版本、当前后端版本、后端提交和构建时间；侧栏显示后端版本，健康接口也返回构建信息。未知的提交或构建时间明确标出，提交时间不会冒充构建时间，包含未提交源码修改的构建会单独提示。
- SSE 兼容通过 `event:` 声明类型的事件。同协议只暂存明确不含输出的启动事件，其余合法扩展、工具、签名和思考事件透传；首字、首内容和是否开始转发分别判断，统计首字不改变重试及首输出超时保护。启动缓存达到上限后按序转发，并保留超时保护；一旦开始转发，不再切换渠道重放。网关自身的响应处理限制（跨协议转换、数据大小）会单独报错，不冷却渠道或自动改用其他渠道，非流式响应也遵循此规则。
- 账户采集使用有限并发，通知投递、历史清理和定时同步独立调度。价格同步默认关闭，模型发现默认每 12 小时执行一次，可在系统设置调整周期，填 0 关闭；手动价格保留。模型首次发现建立比较基准，后续只提示相对上次确认结果的新增及未返回模型，不把主动未选的模型当成新增。可选择“查看并同步”修改所选模型，或“保持当前选择”仅确认本次结果；同一变化不重复提醒，后续有新变化才再次提示。获取失败保留上次成功结果并单独显示错误。

### 请求记录与数据维护

- 系统设置“数据与备份”可下载以自选密码加密的备份，包含一致性数据库快照、主密钥与管理员密码。“恢复备份”支持选择或拖入 `.lgb` 文件，输入备份密码并确认后恢复全部数据；恢复前自动保留原数据，失败会回滚，成功后需重新登录。命令行恢复到新目录的方式继续保留。
- 请求记录和正文只保存在当前进程内存中：保留全部进行中请求，以及最近最多 50 条已结束请求；已结束缓存按序列化记录与正文合计最多 32 MiB，达到条数或容量限制时淘汰最早结束的请求。请求、响应各最多 256 KiB 预览并隐藏常见凭据，不影响实际转发。Go 对象、页面读取时的临时副本和进行中请求另占内存，32 MiB 不是整个程序的内存上限。
- 请求开始即显示记录，列表每 2 秒刷新，支持状态与模型、渠道、密钥名称、请求 ID 搜索，单页显示全部进行中请求和缓存的已结束请求。点击卡片或“查看详情”可查看请求、响应、实时流式片段和上游尝试；缓存淘汰、服务重启或恢复备份后无法再查看这些逐条详情。客户端断开标记取消；重启前尚未结束的请求无法确认最终结果，不补造费用或完成记录。
- 请求结束时，用量、费用、渠道与模型性能汇总及密钥累计已用额度在同一事务中保存。缓存淘汰和重启不清空统计；网关用量、趋势、年度活跃度和渠道/模型表现继续可用。近 24 个小时使用当前小时及之前 23 个小时的汇总，包含尚未结束的当前小时；多日与自选日期仍按北京时间自然日统计。汇总默认保留 365 天，可在设置中调整；监控快照与告警继续默认保留 30 天。每小时清理超期统计，已移除“清除请求数据”及正文/逐条记录保留天数设置。
- 首次升级时，程序先在数据目录 `backups/request-history-*` 留存完整旧库、`master.key` 和管理员密码，再将旧逐条请求转换为小时、每日与渠道/模型汇总，在同一事务中移除在线库中的逐条记录及正文。归档失败会停止升级，不删除请求与正文；汇总或删除失败会回滚整个迁移。已归档每日汇总及密钥累计额度保留，旧版已清理的正文和逐条性能信息不补造。重启不会反复迁移或重复计费；旧正文不再显示在近期请求列表中，可用旧版本在隔离目录打开升级归档。
- 在线数据库删除旧正文后会在空闲期间回收空间。升级归档独立保留，不会自动删除，也不包含在之后下载的 `.lgb` 备份中，因此总磁盘占用不会因为在线数据库缩小而立即下降。首次升级需为旧库副本、迁移及整理预留额外空间；不要只删除数据库或主密钥。确认迁移结果后可自行另存、管理整个归档目录。
- 新备份保存配置、持久化统计、主密钥及管理员密码，不保存内存中的近期请求和正文。完整备份支持最大 4 GiB 数据库，下载、上传及恢复采用流式处理；旧备份仍可恢复，旧请求先归档再转换为统计，归档位于本次恢复工作区。新备份需使用支持 LGB2 格式的版本恢复。
- 请求卡片展示入口与上游协议／模型、密钥名称、推理强度、精确 Token 数、缓存命中率、总耗时、首字及平均 TPS；首内容和输出阶段耗时在请求详情中查看，详情中还保留本次单价与倍率明细。指标按卡片可用宽度分为 10 列、5 列或 2 列，避免单项独占末行。Responses 首字采用 Sub2API 默认语义口径：跳过初始化、元数据和心跳后，首个语义事件（包括空的思考项目开始）即可计时；首内容等待正文、公开思考文本或工具内容，加密思考不算可见内容。均在网关收到事件时取时，失败尝试不沿用到后续成功尝试，先前重试等待仍计入请求延迟。只在完成事件返回内容时，首内容记为整包内容到达时间，无法推算其内部生成时间。平均 TPS 为上游输出总 Token（含推理 Token）除以完整请求耗时，流式及非流式使用相同公式；输出阶段耗时仅描述首内容到流结束，不作为 TPS 分母。模型测试使用相同口径。旧记录原首 Token 仅作为历史首内容显示，未提供的字段不补造、不当成零。
- 请求与响应内容默认折叠，展开后以 JSON 树展示；长字符串和嵌套节点可继续折叠。SSE 事件解析为 JSON，不完整或截断的内容保留可读片段。
- 请求详情读取遇到记录已移出缓存或服务重启时，会停止自动刷新；已经读取的内容保留为最后快照，可继续导出，文件用 source_unavailable 标明原记录已不可用。首次读取即不存在时不提供空文件导出；临时网络错误仍会重试，不补造请求的最终结果。
- 请求详情集中展示时序、状态和诊断，避免重复；进行中的缺失指标显示等待输出、等待用量或等待核算，结束后缺失用量显示未提供，TPS 显示无法计算，缺少有效用量或计价信息时费用显示无法估算。499 显示为客户端断开，表示客户端请求取消或下游连接写入失败，不代表一定由用户主动取消，也不代表上游未收费；请求结束时间统一标为结束于。请求 ID 和每次上游请求 ID 可直接复制，也可导出当前脱敏详情 JSON，包含缓存的正文预览、上游尝试及截断标记；导出进行中请求时只保存当前已获取的快照，不补全已截断内容。

## 行为边界

- 模型测试直接请求指定渠道，不经过负载均衡、故障切换或协议转换，不改变渠道健康状态；请求可能产生上游费用。测试请求以“模型测试”标识计入近期请求和用量汇总，不扣减网关密钥预算；测试正文及完整响应不写入请求记录，保留脱敏的错误信息。使用当前渠道 Key 且模型只有一条匹配路由时，按该路由的单价和倍率估算；使用其他 Key、匹配多个路由、缺少价格或按 Token 计价但缺少完整用量时标记费用未知，以上游账单为准。已发送后取消或响应不完整仍可能收费，不会补算旧测试。测试结果暂存于页面。获取模型仅刷新测试列表；确认移除后才删除该渠道已保存的模型及对应路由，其他渠道和上游站点保留，重新同步可能再次导入这些模型。当前手动路由被移除后需重新选择。
- 模型路由按厂商分类并支持筛选和搜索，厂商根据模型名及上游模型识别，也可在编辑中手动设置。
- 模型路由表每行支持快速移除，仅删除当前模型与渠道之间的这条路由。移除当前手动路由后需重新选择；移除最后一条路由会保留模型配置，暂时无法转发。
- “同步价格”优先读取渠道所属站点的报价：Sub2API 模型广场 `/api/v1/model-plaza`、NewAPI `/api/pricing`，按已确认的密钥分组与用户倍率匹配。每条路由分别保存报价，并展示来源、同步时间、输入／输出及缓存读取、缓存写入 5 分钟／1 小时的单价。
- 账户采集发现已应用站点倍率的自动报价与当前分组或倍率不一致时，会重新读取受影响路由的报价，覆盖输入、输出、缓存和阶梯单价。手动报价、显式参考模型、公共参考价及独立倍率报价不因此改写；失败时保留并标注旧报价，下次采集重试，不追溯修改历史费用。
- 公共参考价依次使用 Models.dev、LiteLLM 和 OpenRouter，部分来源不可用时继续处理其他来源并显示警告。图片／视频保留按张、秒、图片 Token 等计价单位。未经明确选择，不用任意第三方供应商的不同售价覆盖原厂参考价。
- 同一供应商、同一模型且输入输出价一致时，公开目录可补全彼此缺失的缓存单价，保留已明确返回的零价格，并标注补充来源。
- 价格同步通过 `POST /api/groups/sync-prices` 提供，要求管理员登录和请求校验头。账户凭据只发送给关联上游，公共价格目录请求不携带账户凭据。站点价格源暂不可用时保留并标注上次报价。
- 模型别名可填写 `厂商ID/模型ID` 指定参考价，也支持 `litellm/完整模型标识`、`openrouter/厂商/模型`。手动价格支持输入／输出和三种缓存单价；留空表示未知，明确填 0 表示免费，手动设置不会被价格同步覆盖。
- OpenAI Chat、Responses 和 Anthropic 的非流式／流式响应均解析缓存用量，协议转换保留缓存字段。普通输入与缓存读取、缓存写入分别计费，所有项目合计后取整为微美元；站点报价已经应用的分组倍率不会重复乘算。已有请求费用不追溯更改。
- 支持站点返回的整单上下文阶梯，以及 NewAPI 的常见固定价／线性 Token／两档上下文表达式。未知表达式不执行；分段计价和缺少图片／视频数量的已结束请求显示无法估算，分时倍率存在时明确提示为基础估算。

- 后台账户登录状态与推理 API 健康各自记录。后台采集失败会告警，仍可继续转发。开启余额限制后，仅在最新、成功的采集确认余额耗尽时暂停关联渠道，过期的余额数据不作为停用依据。
- 手动选择模式固定使用指定的路由，上游故障、停用或余额限制生效时需手动切换。删除当前渠道后需重新选择路由。加权轮询与优先级模式继续按各自策略调度，已有模型保留原策略。
- 单次请求遇到连接错误或上游故障时按所选策略重试或切换其他可用渠道。上游返回 400 / 422 时返回请求错误。开始向客户端输出之后发生故障，会结束当前流并记录错误，不重放，也不因这一次中断冷却成员或改变后续选路；客户端取消不惩罚上游。
- SSE 需收到协议终止事件并成功写出才计为成功，完成后客户端断开不改记取消。非流式的渠道超时限制完整上游响应时间；流式的渠道超时限制首个有效输出，与系统首输出超时取较小值，出流后由流无数据超时和整次请求总时间上限控制。
- 同协议保留扩展字段。跨协议转换暂不支持有状态 Responses 续接、内建搜索工具、音频、文件、thinking / reasoning 等扩展；结构化输出仅支持 Chat 与 Responses 之间的 JSON 格式映射，其他无法表达的参数会明确报错。
- 有状态 Responses 同协议续接需要配置单一渠道的模型路由。OpenAI 流式转发会向上游请求用量，客户端通过 `stream_options.include_usage=true` 选择接收用量事件。
- 费用使用美元估算，以整数微美元存储。缓存有用量但缺少对应单价时，暂按普通输入价估算并显示原因；已结束请求没有有效用量或可用单价时显示无法估算，费用明细不会把缺失用量当成零。首页及渠道／模型汇总标明费用未知的请求数量，这些请求不计入估算，结束后不会自动补算。公开目录的参考价与所属渠道的最终扣费可能不同，上游真实账单以其后台为准。
- 订阅告警按站点返回的到期时间和 `progress.daily/weekly/monthly` 的剩余额度判断。临近到期为 72 小时内，低余量为 10% 或以下。
- 当前实现面向单实例。轮询权重、渠道冷却和探测占用保存在进程内，重启后重新开始。监控配置、密钥、快照、请求和告警记录保存在 SQLite。
- 当前扩展接口提供采集和查看，账户运维支持编辑、暂停采集、手动采集及管理关联渠道，也可在上游创建密钥并添加为本地渠道。上游充值、订阅购买和远程密钥删除尚未接入。

## 数据与通知

`data/master.key` 用于 AES-256-GCM 加密账户凭据、上游 API Key 和新建网关密钥。网关认证使用 SHA-256 摘要，登录后的管理员可通过复制操作读取对应密钥。密钥列表仅返回前缀和复制可用状态。数据目录和密钥文件需要随数据库一起备份。应停止服务后复制完整数据目录，避免漏掉 SQLite WAL 中的未合并数据。

默认监听所有网络接口，可通过服务器的局域网 IP 访问。需要限制为本机访问时设置 `LEDGERGATE_ADDR=127.0.0.1:8080`。远程访问时按部署环境配置 HTTPS 和访问控制。

通知渠道支持 Telegram Bot、通用 Webhook、SMTP Email、企业微信群机器人、钉钉群机器人、飞书群机器人和 Server酱（SCT / sctp）。Webhook 地址、签名密钥、Bot Token、SendKey 和 SMTP 密码均加密保存，编辑时留空保留原值。邮箱支持 TLS（常用 465）和 STARTTLS（常用 587），使用证书校验，不回退到明文认证。HTTP 通知可逐条选择使用系统设置中的全局代理；SMTP 使用直接连接。

每条渠道可独立订阅账户和事件，不勾选表示全部；倍率变化门槛、订阅阈值和同类告警冷却仍在系统设置统一调整。告警逐渠道排队并持久化，失败只重试对应渠道，默认最多尝试 10 次（包含首次），可设置为 1–30 次。暂停后不接收新告警，已有待发任务等待恢复；删除渠道会取消其待发任务并保留投递历史。删除某账户时会清理对应订阅；若它是渠道最后一个指定账户，则自动暂停该渠道，避免变成订阅全部账户。手动测试发送一次并记录结果，不自动重试。告警详情可展开查看各渠道投递结果，“通知渠道 → 投递记录”可分页查看全部或指定渠道记录，保留周期与告警一致。

首次升级自动将原全局通知配置转换为“原通知渠道”，保留订阅、密钥和队列尝试次数，已送达的历史不会重发。配置导入导出包含所有通知渠道，关闭凭据导出时也移除通知地址；导入后通知渠道默认暂停，旧版单通知配置包仍可导入。

Webhook 使用 JSON，包含 `event`、`title`、`detail`、`account_id`、`alert_id` 和 `created_at`。配置签名密钥后，`X-LedgerGate-Signature` 为 `sha256=` 加原始请求体的 HMAC-SHA256 十六进制摘要。投递按至少一次处理，接收方可用 `alert_id` 去重。飞书与钉钉支持各自的签名方式；钉钉使用关键词校验时可配置关键词 `LedgerGate`。平台的发送额度、限流和机器人安全设置仍由对应服务控制。

钉钉通知使用 Markdown，标题按“上游账户名 · 事件”展示，正文区分余额、采集、倍率、公告、渠道停用和订阅等事件，并附北京时间的检测时间。倍率展示前后值、方向和相对变化幅度，新增和移除分组单独标明；原倍率为零或缺失时不推算百分比。订阅是否到期按事件发生时的时间判断，重试不改变原事件含义。配置签名密钥后正文不再重复 LedgerGate；未配置签名密钥时在末尾保留该关键词，以兼容已有关键词校验。历史告警缺少可解析字段时保留原详情，缺少检测时间时明确标为未记录。
