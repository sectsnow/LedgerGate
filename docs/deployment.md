## 构建和运行

需要 Go 1.26.10 或更新兼容版本，以及 Node.js 22.12+。前端包管理器固定为 pnpm 10.4.0，可通过 Corepack 使用。

```bash
cd LedgerGate
make build
./bin/ledgergate
```

本机打开 <http://127.0.0.1:8080>，局域网设备使用服务器 IP，例如 <http://10.0.0.11:8080>。全新部署首次打开页面时设置并确认 8–72 字节的管理员密码，设置成功后自动登录。密码保存在 `data/admin-password`，后续重启、升级及备份恢复继续使用；已有部署保留原密码。首次设置完成前，应由部署者访问初始化页面。

系统设置中的“更改管理员密码”需要填写当前密码，并两次确认新密码；新密码须为 8–72 字节，首尾不能有空白字符。更改成功后注销全部管理员会话，使用新密码重新登录。密码文件原子替换并保留私有权限，上游凭据的主密钥和网关 Key 不变。使用 `LEDGERGATE_ADMIN_PASSWORD` 覆盖密码的部署由启动配置管理，需在部署配置中修改；移除该变量后，启动时使用密码文件中的密码，再可通过网页修改。登录与改密各按 IP 限制每分钟最多 5 次尝试。

已经构建好的 `bin/ledgergate` 可以直接运行，运行时无需 Go、Node.js 或单独的数据库服务。

### 后台服务

[deploy/ledgergate.service](../deploy/ledgergate.service) 提供 systemd 单实例托管、开机自启和异常退出自动重启，日志由 journald 保存及轮转。模板路径为 `/root/code/LedgerGate`；迁移安装位置时先修改 `WorkingDirectory`、`ExecStart` 和 `ReadWritePaths`。

```bash
systemctl status ledgergate
journalctl -u ledgergate -n 100
systemctl restart ledgergate
```

### Docker 构建与运行

仓库提供多阶段 `Dockerfile`、构建上下文白名单 `.dockerignore` 和单实例 `compose.yaml`。在安装 Docker Engine 与 Docker Compose 的机器上执行：

```bash
docker compose config --quiet
docker compose up -d --build
```

默认访问 `http://服务器IP:8081`，与宿主机上使用 8080 的服务并行验收；全新数据卷通过网页首次设置管理员密码。数据保存到命名卷 `ledgergate_data`，不会打入镜像。从 `0.1.1` 起镜像默认以容器内 root 运行；`0.1.0` 使用 UID 10001，NAS 可通过 `user: "0:0"` 覆盖，详见 Docker 部署说明。

仓库已提供 GitHub Actions 发布工作流：推送 `v*` 版本标签，或在 Actions 中手动运行“发布 GHCR 镜像”，通过源码测试和容器启动、重建检查后上传到 `ghcr.io/sectsnow/ledgergate`。当前构建 `linux/amd64` 镜像。

控制台左下角显示当前后端版本，系统设置的“运行版本”可核对前端版本、后端提交及构建时间；`/healthz` 的 `build` 字段和管理员接口 `/api/version` 返回同一份后端信息。版本号在编译时从 `web/package.json` 嵌入，发布标签必须与该版本一致（如 `0.1.7` 对应 `v0.1.7`），不一致时发布检查会终止。

发布工作流将源码提交号、统一的 UTC 构建时间和源码改动状态注入验收镜像及最终镜像。手动 Docker 构建自动记录构建时间，可通过 `VCS_REF`、`BUILD_DATE`、`VCS_MODIFIED` 构建参数提供完整信息；普通 Go 构建使用 Go 自带的源码提交信息，未注入的构建时间显示未知。包含未提交修改的构建会提示，提交时间不会作为构建时间显示。

完整构建、GHCR 发布与拉取、端口配置、数据挂载、备份和现有数据迁移步骤见 [Docker 部署说明](docker.md)。

### 加密备份与恢复

在系统设置的“备份与恢复”中输入至少 12 字节的备份密码后下载 `.lgb`。数据库通过 SQLite `VACUUM INTO` 生成一致性快照，再流式压缩和分块 AES-256-GCM 加密，密码使用 scrypt 派生密钥。数据库和压缩归档上限提高至 4 GiB，文件上传另允许少量认证信息开销；新格式备份和恢复不再把整个大文件读入内存，临时文件放在数据目录，不使用容器的 `/tmp`。备份密码不保存在服务端。

网页恢复时，在同一位置展开“恢复备份”，选择或拖入 `.lgb` 文件，输入创建该备份时的密码，点击“上传并恢复”并确认替换。格式、密码、全部分块认证、数据库完整性和版本兼容性检查通过后才切换数据；截断、改动、重排分块及尾部多余数据均会被拒绝。恢复会等待正在进行的请求和后台任务结束，期间暂停处理新请求，无需手动重启服务。新生成的 LGB2 备份需使用支持该格式的新版恢复，历史 LGB1 备份继续兼容。

完整恢复会替换当前账户、渠道、模型、密钥、设置和历史。恢复成功后，原实例及备份中的管理员会话全部失效，使用备份中的管理员密码重新登录；如果部署设置了 `LEDGERGATE_ADMIN_PASSWORD`，继续使用该环境变量指定的密码。恢复前的数据和密钥保留在数据目录下的 `backups/restore-*/previous/`，切换失败会自动回滚；若切换时进程中断，下次启动会先回滚到原数据。恢复时需为上传文件、解密副本和恢复前的数据预留磁盘空间。

近期请求和正文仅在内存中保留，最多 50 条已结束请求、32 MiB 序列化数据，进行中请求另计；重启或恢复备份会清空缓存。用量、费用及渠道/模型性能按小时和日期汇总入库，默认保留 365 天，密钥累计已用额度独立持久化。新 `.lgb` 仅包含配置与持久化数据，不包含内存详情或独立归档目录。

首次升级会在数据目录 `backups/request-history-*` 先保留完整旧库、主密钥与管理员密码，再在事务中汇总旧请求并删除在线库中的旧正文及逐条记录。归档失败会停止启动，原请求与正文保留；迁移失败会回滚。若需要查看原始正文，可使用旧版本在归档目录的副本中启动；不要用新程序直接打开唯一一份归档。旧版备份恢复时也会迁移，旧详情归档保存在 `backups/restore-*/request-history/` 下。升级归档含历史敏感数据，仅供本地保管，目录权限为 0700，文件为 0600，不会自动清理或打入新备份。请给旧库副本与数据库整理预留磁盘空间，并在确认统计正确后自行另存或处理归档。

新库启用增量空间回收；删除记录后，空闲页至少 8 MiB 且达到数据库页数的 20% 时，在空闲期间回收空间。旧库首次满足条件时转换为支持增量回收的格式；进行中的网关请求、账户操作、模型测试和备份会推迟整理。整理失败会保留原数据并记录错误，定时维护会重试。在线库缩小不代表独立升级归档的磁盘空间同时释放。旧版程序不支持 LGB2 备份；回退应使用升级前完整归档或备份，升级后产生的统计不会自动同步回旧库。

命令行恢复仍可使用。将密码写入仅自己可读的文件后，可在服务运行期间先恢复到一个尚不存在的新目录：

```bash
./bin/ledgergate restore --file "/path/backup.lgb" --data-dir "/path/restored-data" --password-file "/path/password.txt"
```

恢复会校验归档、密钥文件和数据库完整性，不覆盖已有目录。确认恢复结果后停止服务，在 systemd 中把数据目录配置为恢复位置，再启动服务；`ReadWritePaths` 也需包含新位置。备份含完整账户凭据，应与密码分开保存。

### 选择性配置导入与导出

系统设置中的“数据导入与导出”可复选上游账户、转发渠道、模型与路由、网关密钥、系统设置。导出模型时只补充其引用的渠道及账户；导出渠道时补充关联账户；导出系统设置时补充通知筛选引用的账户。显式勾选某一类别时导出该类别的全部记录。

配置包为 `.lgd`，使用 12–256 字节密码、scrypt 和 AES-256-GCM 加密，单包限 16 MiB、单类限 10000 条。可选择是否包含账户密码、访问/刷新令牌、Cookie、附加登录参数、渠道 Key、完整网关 Key、代理配置及通知凭据；关闭时不导出全局代理地址和认证信息，代理启用状态也不随包启用，同时不导出通常包含令牌的机器人 Webhook 地址。配置包不包含管理员密码、主密钥、登录会话、消费历史或请求正文；配置与持久化用量统计的完整恢复使用 `.lgb` 备份。

已保存的网站 Logo 随账号导出，不受是否包含凭据影响，也包含在完整备份中。带 Logo 的配置包使用 v2 格式，需要支持该格式的版本导入；不带 Logo 时继续使用 v1，旧 v1 配置包仍可导入。已有账号只补齐缺失或已更换站点的自动图标，保留本地已保存的有效图标与手动 Logo。

导入支持选择文件和拖入文件，先解密预览文件内的类别、新增、跳过与替换数量，再勾选需要的内容并确认。账户按名称、站点类型、地址和用户身份匹配，渠道按关联账户与上游 Key ID（无上游 ID 时按名称、地址和协议）匹配，统一模型按名称匹配，网关密钥按摘要匹配；已有项保留原配置，跳过的模型也不追加或替换其路由。预览绑定当前管理员会话、文件和配置版本，15 分钟有效；文件、选择或配置变化后需重新预览。

导入在单个事务中完成，失败整体回滚；源 ID 重新映射为目标 ID，凭据以目标主密钥重新加密。新账户、渠道和网关密钥默认停用，缺失凭据需补填后启用；原有密钥预算和累计费用保留。路由的自动报价保留数值但标记待重新同步。选中系统设置时会替换目标的通知、网络代理、运行参数和保留策略，不改变目标管理员密码或登录会话；未包含代理配置的数据包会将全局代理关闭并清空。

### 运行参数

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `LEDGERGATE_ADDR` | `0.0.0.0:8080` | 监听地址，默认允许局域网访问 |
| `LEDGERGATE_DATA_DIR` | `data` | 数据目录，相对于进程工作目录 |
| `LEDGERGATE_ADMIN_PASSWORD` | 从密码文件读取；全新部署通过网页设置 | 覆盖管理员密码，长度 8–72 字节；预设后直接进入登录页，由部署配置更改 |

### 开发环境

开发时分别启动后端与前端。

```bash
go run ./cmd/ledgergate
```

```bash
cd web
corepack pnpm install --frozen-lockfile
corepack pnpm dev
```

前端开发服务将 `/api` 和 `/v1` 转发到 `127.0.0.1:8080`。构建前端后需重新构建或启动 Go 程序，才能更新嵌入的页面。

## 验证

```bash
go test -race ./...
cd web
corepack pnpm test
corepack pnpm build
```

自动化测试使用独立的临时数据库和本地模拟上游，覆盖管理鉴权、凭据保护、正常 API 配置入口、并发加权分流、故障切换、流中断、协议转换、用量和费用、账户登录、监控告警、Webhook 重试与重启后的解密。

真实站点的魔改登录、接口差异、客户端扩展协议和生产并发性能仍需使用实际账户验证。
