## 构建和运行

需要 Go 1.26.10 或更新兼容版本，以及 Node.js 22.12+。前端包管理器固定为 pnpm 10.4.0，可通过 Corepack 使用。

```bash
cd LedgerGate
make build
./bin/ledgergate
```

本机打开 <http://127.0.0.1:8080>，局域网设备使用服务器 IP，例如 <http://10.0.0.11:8080>。全新部署首次打开页面时设置并确认 8–72 字节的管理员密码，设置成功后自动登录。密码保存在 `data/admin-password`，后续重启、升级及备份恢复继续使用；已有部署保留原密码。首次设置完成前，应由部署者访问初始化页面。

系统设置中的“更改管理员密码”需要填写当前密码，并两次确认新密码；新密码须为 8–72 字节，首尾不能有空白字符。更改成功后注销全部管理员会话，使用新密码重新登录。密码文件原子替换并保留私有权限，上游凭据的主密钥和网关 Key 不变。使用 `LEDGERGATE_ADMIN_PASSWORD` 覆盖密码的部署由启动配置管理，需在部署配置中修改；移除该变量后，启动时使用密码文件中的密码，再可通过网页修改。登录与改密各按 IP 限制每分钟最多 5 次尝试。

已经构建好的 `bin/ledgergate` 可以直接运行，运行时无需 Go、Node.js 或单独的数据库服务。

### 后台服务

[deploy/ledgergate.service](../deploy/ledgergate.service) 提供 systemd 单实例托管、开机自启和异常退出自动重启，日志由 journald 保存及轮转。模板路径为 `/root/code/LedgerGate`；迁移安装位置时先修改 `WorkingDirectory`、`ExecStart` 和 `ReadWritePaths`。

```bash
systemctl status ledgergate
journalctl -u ledgergate -n 100
systemctl restart ledgergate
```

### Docker 构建与运行

仓库提供多阶段 `Dockerfile`、构建上下文白名单 `.dockerignore` 和单实例 `compose.yaml`。在安装 Docker Engine 与 Docker Compose 的机器上执行：

```bash
docker compose config --quiet
docker compose up -d --build
```

默认访问 `http://服务器IP:8081`，与宿主机上使用 8080 的服务并行验收；全新数据卷通过网页首次设置管理员密码。数据保存到命名卷 `ledgergate_data`，不会打入镜像。镜像中的程序使用非 root 用户运行。

仓库已提供 GitHub Actions 发布工作流：推送 `v*` 版本标签，或在 Actions 中手动运行“发布 GHCR 镜像”，通过源码测试和容器启动、重建检查后上传到 `ghcr.io/sectsnow/ledgergate`。当前构建 `linux/amd64` 镜像。

完整构建、GHCR 发布与拉取、端口配置、数据挂载、备份和现有数据迁移步骤见 [Docker 部署说明](docker.md)。

### 加密备份与恢复

在系统设置的“备份与恢复”中输入至少 12 字节的备份密码后下载 `.lgb`。备份使用 scrypt 和 AES-256-GCM，数据库通过 SQLite `VACUUM INTO` 生成一致性快照，单个数据库及加密归档限 256 MiB。备份密码不保存在服务端。

将密码写入仅自己可读的文件后，可在服务运行期间先恢复到一个尚不存在的新目录：

```bash
./bin/ledgergate restore --file "/path/backup.lgb" --data-dir "/path/restored-data" --password-file "/path/password.txt"
```

恢复会校验归档、密钥文件和数据库完整性，不覆盖已有目录。确认恢复结果后停止服务，在 systemd 中把数据目录配置为恢复位置，再启动服务；`ReadWritePaths` 也需包含新位置。备份含完整账户凭据，应与密码分开保存。

### 选择性配置导入与导出

系统设置中的“数据导入与导出”可复选上游账户、转发渠道、模型与路由、网关密钥、系统设置。导出模型时只补充其引用的渠道及账户；导出渠道时补充关联账户；导出系统设置时补充通知筛选引用的账户。显式勾选某一类别时导出该类别的全部记录。

配置包为 `.lgd`，使用 12–256 字节密码、scrypt 和 AES-256-GCM 加密，单包限 16 MiB、单类限 10000 条。可选择是否包含账户密码、访问/刷新令牌、Cookie、附加登录参数、渠道 Key、完整网关 Key、代理配置及通知凭据；关闭时不导出全局代理地址和认证信息，代理启用状态也不随包启用，同时不导出通常包含令牌的机器人 Webhook 地址。配置包不包含管理员密码、主密钥、登录会话、消费历史或请求正文，完整历史恢复继续使用 `.lgb` 备份。

导入支持选择文件和拖入文件，先解密预览文件内的类别、新增、跳过与替换数量，再勾选需要的内容并确认。账户按名称、站点类型、地址和用户身份匹配，渠道按关联账户与上游 Key ID（无上游 ID 时按名称、地址和协议）匹配，统一模型按名称匹配，网关密钥按摘要匹配；已有项保留原配置，跳过的模型也不追加或替换其路由。预览绑定当前管理员会话、文件和配置版本，15 分钟有效；文件、选择或配置变化后需重新预览。

导入在单个事务中完成，失败整体回滚；源 ID 重新映射为目标 ID，凭据以目标主密钥重新加密。新账户、渠道和网关密钥默认停用，缺失凭据需补填后启用；原有密钥预算和累计费用保留。路由的自动报价保留数值但标记待重新同步。选中系统设置时会替换目标的通知、网络代理、运行参数和保留策略，不改变目标管理员密码或登录会话；未包含代理配置的数据包会将全局代理关闭并清空。

### 运行参数

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `LEDGERGATE_ADDR` | `0.0.0.0:8080` | 监听地址，默认允许局域网访问 |
| `LEDGERGATE_DATA_DIR` | `data` | 数据目录，相对于进程工作目录 |
| `LEDGERGATE_ADMIN_PASSWORD` | 从密码文件读取；全新部署通过网页设置 | 覆盖管理员密码，长度 8–72 字节；预设后直接进入登录页，由部署配置更改 |

### 开发环境

开发时分别启动后端与前端。

```bash
go run ./cmd/ledgergate
```

```bash
cd web
corepack pnpm install --frozen-lockfile
corepack pnpm dev
```

前端开发服务将 `/api` 和 `/v1` 转发到 `127.0.0.1:8080`。构建前端后需重新构建或启动 Go 程序，才能更新嵌入的页面。

## 验证

```bash
go test -race ./...
cd web
corepack pnpm test
corepack pnpm build
```

自动化测试使用独立的临时数据库和本地模拟上游，覆盖管理鉴权、凭据保护、正常 API 配置入口、并发加权分流、故障切换、流中断、协议转换、用量和费用、账户登录、监控告警、Webhook 重试与重启后的解密。

真实站点的魔改登录、接口差异、客户端扩展协议和生产并发性能仍需使用实际账户验证。
