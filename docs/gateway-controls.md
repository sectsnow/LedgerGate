# 网关预算、排障摘要与采集状态

本页说明 v0.1.15 新增功能。继续使用单实例、SQLite，不增加外部服务；发布版本不代表生产服务器已经升级。

## 网关 Key：周期预算与流量限制

在“网关密钥 → 编辑限制”配置：

- 累计预算继续保留；可额外设置每日、每月美元预算。留空不限，明确填 0 表示禁止新推理请求。
- 周期按北京时间每日零点、每月 1 日零点重置，页面展示已用量与重置时间。达到 80% 提示接近预算，达到上限拒绝新推理请求；提醒目前在管理页面展示，不新增外部推送。
- 最大并发与每分钟请求上限填 0 表示不限。流式请求直到结束或取消才释放并发位置；每分钟限制采用滚动 60 秒窗口，返回 429 与 Retry-After。流量窗口和在途计数在进程内保存，服务重启或恢复备份后重置。
- 周期预算使用独立的持久化每日用量，按请求开始日计入。修改预算不清空已用额度。未知费用不计入；在途请求仍可能产生费用，所以这些限制不等于上游实际账单的严格硬上限。
- “用量历史”展示最近 90 天的请求数、估算费用、费用未知数量。日用量最多保留 400 天，不随请求摘要清理。第一次升级不会从既有汇总反推每个 Key 的历史数据，周期账本从升级后的请求开始记录。
- 配置包携带预算与流量限制，但不携带周期账本；导入端 Key 默认停用，累计已用费用沿用原配置包逻辑。完整备份则包含全部周期用量。

## 请求记录：近期正文与历史摘要

“请求记录”提供两个入口：

- **近期与正文**：保留原来的内存缓存，最多 50 条已结束请求、32 MiB 序列化数据；进行中请求另计。服务重启后清空。
- **历史摘要**：保存请求 ID、时间、模型、渠道、Key 名称、状态、用量、当时费用估算与最多 32 次上游尝试的元数据。可以搜索、按状态筛选、分页、查看和导出，重启后仍可读。

摘要不保存请求/响应正文、认证头、计价明细或上游错误原文；失败原因使用固定诊断分类，选路原因归类为等待、重试、切换或恢复探测。它用于定位问题，不能替代仍在内存中的详细错误证据。摘要中的已知费用沿用完成时结果，费用未知不显示为零。

“系统设置 → 排障摘要保留”可设置 1–90 天、1–100000 条，默认 7 天、5000 条，同时受两者限制；不应把摘要当作永久审计档案。清理摘要不会删除用量汇总或 Key 预算；摘要单独写入事务，写入失败会记录错误日志，不回滚已经保存的用量和预算。首次升级不会为已丢失的请求正文或未保留的历史请求补造摘要。

## 同模型渠道比较

“渠道与模型表现”可选择统一模型，再按请求数、成功率、平均首字或每请求费用排序，显示样本量、最近使用时间以及首次成功、重试成功、最终未成功和重试前耗时。

- 尝试统计从升级后的新请求开始记录；旧汇总仍参与原有成功率与费用统计，但缺失尝试数据标为未记录。
- 至少两个渠道各有 20 次同模型请求才给出成功率、首字参考，不自动改路由。
- 请求及其全部重试前耗时归属最终渠道，不能据此认定每个曾被尝试渠道的独立成功率。取消也计入未成功。
- 每请求费用取决于输入输出、缓存和工作负载，不是模型单价。费用不完整时明确标注，不以缺失费用推荐“最便宜”。
- 仅展示实际已有的均值，不从均值推算 P95。

## 分项采集状态与报价时间线

概览及账户卡片可以展开“分项采集状态与报价时间线”，分别查看余额、累计消费、今日实际消费、倍率、订阅、公告与自动报价。

- 最近尝试与最近成功分开保存，接口失败不会推进成功时间。未执行、未接入、未知和失败分别显示；暂停监控时保留历史结果。
- 成功时间超过采集周期两倍时标为旧数据。历史未记录成功时间不通过最后检查时间推测。
- 记录倍率快照变化与随后自动报价更新成功/失败；更新失败保留旧报价并在后续采集重试。其他价格同步占用时标记等待。
- 每个账户最多保留 100 条倍率/自动报价事件、保留 30 天，面板显示最近 50 条。报价时间线只表示倍率变化触发的自动报价更新，不代替全量手动同步任务记录；后者仍在系统设置查看。
- 配置导入导出不把源站的采集状态当成目标站的实时状态；完整备份保留分项记录。删除账户一并删除对应时间线。

## 兼容与验收

新增表为 Key 日用量、请求摘要和采集事件；账户、密钥及小时汇总增加兼容字段。启动时自动迁移，升级前应备份整个数据目录。新表不会补造旧账本、旧采集成功时间或旧重试统计。旧版程序不执行新增的周期预算、并发和频率限制，回退不能沿用这些限制的保护承诺；需要完整回退时使用升级前的数据目录备份。
