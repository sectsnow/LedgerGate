# 桌面小部件：贴边收起与数据浮标方案（本地已实现，Windows 实机待验收）

制定及实施日期：2026-11-25。已完成本地源码实现和自动验证，纳入 v0.1.14 发布范围，未部署生产。保留原方案文件名以便追溯；下文记录方案与实际实现差异，真实 Windows 验收尚未完成。

## 1. 决策

采用“完整面板 + 数据浮标”的统一交互：完整面板拖到屏幕左、右边缘后可自动收成数据浮标，也可以手动收起为可自由拖动的浮标。隐藏到系统托盘继续作为独立操作保留。

浮标优先使用约 72×56 逻辑像素的圆角胶囊，上行标注指标，下行显示一个数值与状态标记。相比真圆形，胶囊更适合金额、币种和较长数字；它是同一个浮标的呈现方式，不再提供另一套“球/胶囊”配置。

完整总览继续包含用量、账户、模型/渠道排行、分析趋势和告警；专项标签也保留。收起只改变窗口呈现，不删内容，不把完整总览再次拆散。

| 选择 | 优点 | 主要问题 | 决策 |
| --- | --- | --- | --- |
| 仅贴边隐藏为窄条 | 占地极小 | 数据难读，入口不明显 | 不作为默认形态 |
| 仅独立悬浮球 | 容易发现，可放任意位置 | 仍会遮挡桌面，需要手动管理 | 作为手动收起后的同一浮标 |
| 贴边收起 + 可拖动数据浮标 | 兼顾完整阅读、随时看数和减少遮挡 | 需要统一窗口状态和尺寸切换 | 推荐采用 |

## 2. 调研依据及取舍

### Token Monitor：最直接的参考

核对仓库快照 `13629533efce37f69c8f9f0b1bd2efc3e9b1a10d` 的 README、`floatingBubble.js`、`edgeDock/controller.js`、`edgeDock/geometry.js` 以及浮标测试。

- README 明确列出 Windows/macOS Edge Dock，包含自动隐藏、常驻和全屏避让模式；Floating Bubble 支持拖动、点击或悬停预览。

- Dock 使用不主动取得焦点的窗口策略，并对鼠标意图设置延迟，避免掠过屏幕边缘时不断展开。
- LedgerGate 借鉴模式切换、边界计算、延迟防抖、完整状态恢复及测试方法。不会照搬 Electron 窗口 API、macOS 原生玻璃或完整 Dock 布局编辑器。

### Windows 平台规范

- 微软 `MONITORINFO.rcWork` 定义的是每个显示器的可用工作区，副屏坐标允许为负数。面板和浮标以工作区为边界，避让任务栏；多屏内部接缝不默认触发贴边收起。
- 微软高 DPI 文档强调跨不同缩放率显示器、插拔外接屏和远程桌面都会改变 DPI。尺寸用逻辑像素、位置按物理坐标处理，并在跨屏后重新计算。
- 微软 `SetWindowPos` 文档区分置顶和激活，`SWP_NOACTIVATE` 用于避免激活窗口。数据刷新、吸附与收起不抢用户正在输入的焦点，明确点击展开时才允许聚焦。
- 微软 Notification Area 指南主张状态显示应克制、不持续闪烁、不频繁改变；该文档基于 Windows 7，本方案只引用这些交互原则，不将其称为 Windows 11 的最新视觉规范。
- W3C 关于悬停内容的原则是可关闭、可移入、能持续阅读。首版不使用“鼠标一经过就弹完整面板”的行为，降低误触和键盘操作风险。

来源：

- [MONITORINFO 与工作区](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-monitorinfo)
- [Windows 高 DPI 桌面开发](https://learn.microsoft.com/en-us/windows/win32/hidpi/high-dpi-desktop-application-development-on-windows)
- [SetWindowPos 与不激活窗口](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)
- [Notification Area 交互原则](https://learn.microsoft.com/en-us/windows/win32/uxguide/winenv-notification)
- [W3C：悬停或焦点产生的内容](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html)

上述调研事实与下文的产品设计分开：72×56 尺寸、收起延迟及轮播间隔是 LedgerGate 的初始设计值，实施时需用实机验证，不是平台强制标准。

## 3. 交互规则

### 3.1 进入和退出

- 默认启动仍显示完整面板，不自动把现有用户的小部件藏起来；已有浮标偏好则恢复浮标。
- 提供“贴边自动收起”选项，初始开启，但只有用户完成向左/右侧外边缘的拖动并吸附成功后才生效；普通浮动位置不自动收起。
- 完成拖动后距离边缘约 16 逻辑像素内吸附；拖离约 32 像素后脱离吸附。使用不同进入/退出阈值避免边缘抖动。
- 吸附的面板在鼠标离开且面板失焦约 800ms 后收起。设置表单、菜单、拖动、键盘操作或转换进行中不自动收起；操作完成后重新计时。
- 单击浮标，向屏幕内部展开完整面板，恢复之前的标签、统计周期和宽度，再按当前内容适配高度。
- 悬停浮标显示指标名称、精确数值、数据时间和“单击展开”的说明。首版采用系统原生 `title` 提示，出现时机和关闭由 WebView2 管理，不实现可移入的自定义提示层；触屏用户直接点按展开。
- 面板新增“收起为浮标”操作；未贴边时得到自由浮标。该操作不复用关闭按钮，也不篡改 Windows 系统最小化含义。
- 自由浮标可拖动，拖动超过约 6 逻辑像素判为拖动而非点击；拖到可用边缘可转为贴边浮标。
- 现有“隐藏到托盘”仍真正隐藏窗口，不留下浮标；托盘“显示完整面板”始终可恢复。另提供“重置位置”，处理窗口不可见或异常状态。
- “置顶”与“保持展开”含义分开。保留既有置顶偏好，贴边面板可通过菜单选择保持展开，避免阅读时收起。

### 3.2 窗口状态

| 状态 | 画面 | 退出路径 |
| --- | --- | --- |
| 自由面板 | 完整总览或专项视图 | 拖到边缘；手动收为浮标；隐藏到托盘 |
| 贴边面板 | 向屏内展开的完整面板 | 离开并失焦后收起；拖离边缘；保持展开 |
| 贴边浮标 | 边缘的数据胶囊 | 单击展开；拖离边缘；托盘恢复 |
| 自由浮标 | 可任意放置的数据胶囊 | 单击展开；拖至边缘；隐藏到托盘 |
| 托盘隐藏 | 只有既有托盘入口 | 托盘显示完整面板或重置位置 |

显示视图（总览/账户/分析/告警/排行）与窗口状态分别保存。展开时返回原来的完整内容，不因模式切换丢失视图或周期。

### 3.3 浮标数据

首版支持四类指标，默认固定显示“今日 Token”：

| 指标 | 浮标示例 | 数据口径 |
| --- | --- | --- |
| 今日 Token | `今日 Token / 25.9M` | 现有概览顶层今日输入 + 输出 Token |
| 今日请求 | `今日请求 / 99` | 现有概览顶层今日已结束请求数 |
| 账户余额 | `余额 USD / $12.34` | 所选币种的已知余额合计，提示采集覆盖 |
| 今日实际消费 | `今日 USD / $1.20` | 所选币种、采集日期匹配今日的上游实际消费 |

- 多币种不相加；存在多个币种时金额指标需明确选择币种，并在浮标上标出单位。
- 小窗使用带单位的紧凑数字，展开或悬停显示精确值；超长金额缩写，不挤掉标签。
- 浮标“今日”独立于完整面板的今日/近7天/近30天选择，不能将一个月的总量显示成今日。
- 可选开启浮标数据轮播，默认关闭；开启后每 8 秒切换用户选中的指标，默认候选为今日 Token 与今日请求。鼠标悬停、拖动、菜单打开时暂停，避免数值在阅读时变化。
- 面板视图轮播与浮标指标轮播各自有开关；浮标模式不在后台轮换面板标签，展开后保持原标签。
- 断线、凭证失效或采集过期时保留最后值并明确标记“旧数据”/异常状态，不归零，不以绿色状态点暗示实时正常。
- 接口刷新时间和账户最后采集时间分别显示；跨北京时间零点后，旧日期数据不能继续无标记地称为“今日”。

### 3.4 告警和不打扰

- 正常时保留细小状态点；异常时使用色点加文字/图形标记，不能只依赖颜色。
- 告警不强制展开面板，不抢焦点、不持续闪烁、不自动播放声音。点开后可进入既有告警内容。
- 自动折叠、数据刷新和轮播不改变其他应用焦点；用户主动点击展开时才激活可交互面板。
- 浮标开启时默认避让其所在显示器的前台全屏应用；检测到全屏后暂时隐藏，退出全屏后恢复先前状态。不得用其他屏的全屏状态隐藏所有显示器上的入口。
- Windows 原生通知不纳入本次范围。已有小部件告警仍属于本地数据提示，不宣称新增了阈值推送或系统 Toast。

## 4. 实现方案

### 4.1 优先采用同一 Tauri 窗口切换形态

使用现有 `main` 窗口，在完整面板与数据浮标之间切换，复用一份 React 数据状态和一条现有刷新链路。首版不新增第二个常驻 WebView、第二套凭证或独立数据轮询。

现有配置把主窗口最小尺寸限制为 360×360，并且 `App.tsx` 已包含完整视图自动适配高度逻辑。仅修改 CSS 无法变成小浮标，必须同步切换原生约束。

进入浮标时：锁定模式转换 → 保存面板几何 → 暂停面板自动适配 → 设置浮标尺寸约束及可调整属性 → 定位/切换到浮标 → 提交模式。恢复面板时按 Tauri/Windows 实测的正确顺序解开浮标约束、恢复完整面板限制与位置，完成后再启用内容高度适配。

不能原样照搬 Token Monitor 的 Electron 调用顺序；它的相关测试说明这里确实容易出问题，本项目需要独立验证。

转换失败时回滚到可见的完整面板，并提供托盘恢复；不允许应用存活但面板和浮标都不可见。模式转换执行期间合并连续点击，避免最后一次显示意图被旧异步调用覆盖。

### 4.2 位置记忆与边界

- 原有 `ledgergate-widget-window-state` 保持面板用途，浮标的72×56不能被写进去后污染完整面板恢复。
- 单独记录窗口模式、浮标位置、贴边侧和沿工作区高度的相对比例；独立保存指标、币种和轮播开关。缺失或损坏配置回退为可见的完整面板。
- 使用现有逻辑尺寸/物理坐标规则，浮标和面板分别计算边界；跨DPI显示器重新测量，不能复用另一个显示器的旧物理宽高。
- 仅默认支持左、右外边缘；相邻显示器接缝、顶部系统交互区、底部任务栏附近不自动吸附隐藏。
- 展开向屏幕内部放置，靠近底部时上移；显示器断开、工作区变化或远程桌面分辨率改变时修正到有效显示器。
- 面板与浮标都不能整体移出屏幕，只留下不可读的小缝；原生窗口命中区域应接近实际可见浮标，避免透明大窗口拦截桌面点击。

### 4.3 刷新和性能

- 继续复用小部件只读接口及默认 30 秒刷新节奏，不因为展开、折叠或指标轮播增加上游采集。
- 浮标指标使用既有顶层今日字段、`accounts` 和 `finances`，首版无需新增服务端接口或数据库结构。
- 只更新可见的指标文本；轮播不触发网络请求。隐藏的图表停止动画和观察器，展开时读取同一份最新快照。
- 不在 React 中运行每16ms的全局鼠标轮询。吸附以拖动结束/移动事件为主；全屏检测优先系统事件，必要时由原生层低频检查。
- 进出托盘、睡眠唤醒和 WebView 定时器可能被系统节流，恢复可见时重新确认数据；超时则保留过期标记，不能依靠旧的刷新定时器假定数据始终新鲜。

### 4.4 文件范围

| 文件 | 计划内容 |
| --- | --- |
| `widget/src/App.tsx` | 连接模式控制；保留完整总览；按模式启停适配高度与视图轮播 |
| `widget/src/windowState.ts` | 区分面板/浮标几何；处理吸附、展开和多屏恢复；保留现有调用兼容 |

| `widget/src/WidgetDisplaySettings.tsx`（新增） | 复用现有面板的设置入口，管理贴边、指标与轮播 |
| `widget/src/summary.ts` | 复用现有财务汇总；必要时补纯函数选择/格式化浮标指标 |

| `widget/src-tauri/src/main.rs`、`desktop_display.rs`、`environment.rs` | 窗口原生命令、托盘恢复/重置、Windows 全屏检测、工作区变化和不抢焦点恢复 |
| `widget/src-tauri/capabilities/default.json` | 只增加模式转换实际需要的窗口权限 |
| `widget/src-tauri/tauri.conf.json` | 核验窗口形态、透明圆角和尺寸配置；保持原面板默认行为 |

原生圆角、透明背景、点击与焦点行为是技术预验证门槛。若同窗模式在目标 Windows/WebView2 版本上出现无法稳定解决的问题，先记录实证，再改为“主面板 + 一个小型浮标窗口”；只有在此情况下才引入跨窗口共享快照，不直接上多窗口架构。

## 5. 实施顺序与完成条件

本地实施状态：步骤 2—4 已落地，步骤 1 完成编译与链接验证但未在 Windows 上完成原生交互门槛验收，步骤 5 完成自动验证与文档，保留实机验收项。

1. **原生可行性预验证**：验证同一窗口在完整面板和72×56浮标间往返、约束恢复、拖动、置顶、不抢焦点和圆角命中。未通过前不投入完整动画与样式开发。
2. **手动数据浮标**：实现手动收起、单击展开、拖动、独立位置记忆和托盘恢复。保留完整总览及其自适应高度，这是可独立验收的第一批。
3. **贴边与避让**：接入左右吸附、失焦收起、拖离恢复、工作区/DPI修正和同屏全屏避让。
4. **数据与轮播**：补四类指标、币种选择、指标轮播、旧数据标记与交互暂停；不增加请求频率。
5. **集成验收和文档**：运行针对性自动测试和真实 Windows 体验验证，完成后再按明确的发版指令更新版本、镜像和 Windows 两种包。

## 6. 验收清单

- 完整总览所有原有内容仍存在；面板/浮标往返后标签、周期、主题、宽度不丢失。
- 连续快速展开/收起、自动轮播与自动高度同时触发时，最终模式正确，无反复变大/缩小。
- 浮标可自由拖动；拖动结束不会误触展开；靠近但未吸附时不会突然消失。
- 点击、右键菜单、触屏点按及托盘键盘恢复都可使用，不依赖悬停才能展开。
- 面板输入凭证、打开菜单、键盘阅读或设置保持展开时，不被自动收起打断。
- 100%、125%、150%、200%缩放率；左右多屏、负坐标、跨屏、拔屏、任务栏位置/自动隐藏、休眠与远程桌面分辨率变化均有验证记录。
- 同屏全屏后浮标避让，退出后恢复；副屏全屏不误伤当前屏；自动变化不抢其他应用输入焦点。
- 完整面板大小记忆不被浮标尺寸覆盖；配置损坏或转换API失败时可通过托盘恢复完整面板。
- 今日指标与面板近7/30天选择独立；USD/CNY不相加；无值、未采集、暂停、过期、断线、凭证撤销和跨日不会被显示为正常零值。
- 指标轮播不发请求，面板与浮标只有一条刷新链路；状态提示不闪烁、不强制展开。
- Windows 实机验证透明圆角附近没有大片不可见区域吞掉点击；与浏览器模拟通过分别记录。

## 7. 首版明确不做

不做任务栏嵌入、顶部/底部四边吸附、额外悬停大面板、自定义布局编辑器、全局快捷键系统、鼠标穿透、持续呼吸闪烁动画、系统Toast或新后端统计接口。保留托盘作为可靠恢复入口。首版直接切换原生窗口尺寸，不增加窗口缩放动画，避免与高度自适应竞争；既有加载动画仍遵循减少动态效果设置。

实施保留了工作区已有完整总览恢复和窗口高度适配修改，未改动其他后端与管理页面工作。

## 8. 实施与验证记录

- 同一窗口、一份 React 数据快照及既有 30 秒读取链路；没有新增依赖、服务端接口或数据库格式。浮标模式暂停完整面板适配高度与页面轮播，指标轮播只更新本地文本。
- 窗口变换串行执行，合并过期请求；浮标与面板几何分开保存。失败时尝试恢复完整面板，托盘入口直接在原生层恢复，避免依赖前端转换成功。
- 移动/缩放事件防抖，拖动结束再吸附；原生层每秒检查同屏前台全屏及显示器工作区变化，恢复唤醒后通知刷新。窗口变换及状态锁均在 UI 线程处理，后台线程不持锁等待窗口 API。

- 仍待 Windows 实机：各 DPI 下透明圆角命中、原生拖动与菜单焦点、同屏/异屏全屏避让、多屏热插拔、任务栏变化、休眠及远程桌面恢复。原生 `title` 提示与无缩放动画是首版明确简化，不宣称完成原方案的自定义悬停层。
